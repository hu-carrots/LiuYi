# 六一 · 桌面宠物 v2.2 + 第一期 — 优化说明 / 使用说明 / 评价

小猫叫**六一**，是一只海豹双色布偶。v2.2 起代码已拆进 `ragdollpet/` 包，**接口不变、老配置自动沿用**。依赖仍只有 `PyQt5==5.15.11`（见 `requirements.txt`）。

## 使用说明

### 跑起来

```powershell
pip install -r requirements.txt   # 只装一次，主程序依赖
python desktop_pet_v2.1.py        # 启动器（历史文件名，见“目录结构”说明），代码在 ragdollpet\
```

- 双击 `desktop_pet_v2.1.py` 也行（关联了 .py 的话）。
- **自动单实例**：重复启动不会出现两只猫，第二次启动会把已经在跑的那只叫到前面然后自己退出。
- 关掉窗口（Alt+F4）＝退出程序并保存位置，不会留后台进程。

### 它什么时候会做什么

| 状态 | 触发条件 | 表现 |
|---|---|---|
| 待机 | 默认 | 呼吸帧循环（待机 → 吸气 → 呼气，每帧约 1.2 秒）、随机眨眼、偶尔甩尾，18–35 秒说一句 |
| 散步 | 待机 60–120 秒后 | 8 帧步态循环（一轮约 1 秒），水平移动 2px/帧，撞到屏幕边自动转身 |
| 浅睡 | **5 分钟**没碰它 | 先打一个哈欠（约 1.2 秒，图缺了直接睡），再换睡觉呼吸帧循环（睡觉 → 吸气 → 呼气，每帧约 1.2 秒）+ Zzz，鼠标悬停即醒 |
| 深睡 | **10 分钟**没有键盘鼠标（全系统） | 同上 + 整体半透明 0.55，动一下键鼠 1 秒内醒，35% 概率伸懒腰、35% 概率说"你回来啦" |
| 伸懒腰 | 待机 90 秒以上随机 / 深睡醒来 35% / 右键手动 | 蹲着准备 → 前爪前伸，两帧循环约 1.8 秒后回待机 |
| 打哈欠 | 待机 90 秒以上随机 / 睡前 / 右键手动 | 小口微张 → 大口捂嘴，两帧循环约 1.8 秒后回待机 |
| 抛掷 | 拖动后快速松手（>500px/s） | 沿抛物线飞（甩出/翻滚两帧交替，约每 120ms 换一帧），落回起抛点同一高度，全程不出屏幕；落地帧约 0.25 秒 + 晕乎约 1.2 秒后回待机；飞行中抓住取消 |
| 推图标 | 扒拉文件随机触发 / 右键“推一下桌面图标”（仅 Windows，free 模式） | 走到一个真实文件图标旁，用推帧推它，图标跟着爪子挪约 32px、说出文件名；每次只推一个图标，图标不出屏幕；原始位置记在 `icon_layout_backup.json`，右键“把图标放回去”一键恢复；中途抓住猫、点它一下、关动画或省电都会取消 |
| 被摸 | 单击 | 眯眼蹭头 0.7 秒 |
| 炸毛 | 350ms 内连点第二次 | 跳一下 + 炸毛台词 |
| 跳跃 | 没有 `cat_pet.png` 时的单击 | 跳一下 + 台词 |

两个时间都能在设置里改，浅睡和深睡互不干扰（浅睡按"没摸猫"算，深睡按"人不在"算）。

### 鼠标 / 键盘

| 操作 | 效果 |
|---|---|
| 左键单击 | 摸它（眯眼） |
| 快速连点 | 炸毛跳 |
| 左键拖动 | 拖着换位置，**拖不出屏幕**（至少 80px 留在屏内）；松手时甩得够快就抛出去，沿抛物线落回同一高度 |
| 滚轮（指在猫身上） | 缩放 0.5×–2.5×，只吃猫身体那部分的滚轮，旁边滚是滚桌面 |
| 右键 | 打开菜单 |
| 悬停 | 浅睡时叫醒它 |

猫身上的"可点区域"是跟着图片轮廓走的（窗口 mask），点透明的地方是点桌面。

### 说话气泡

气泡现在是**贴着六一的头顶**（间隙 6px），不再按窗口顶边算——窗口顶部有 64px 透明留白，旧版气泡离猫头有 95px，看着像飘在半空。睡觉时六一压低，气泡也会跟着降到它实际的头顶；头顶放不下才翻到脚下。

启动时会说一句「我是六一，今天也陪着你～」，喝水提醒、设置窗口标题、右键菜单也都带上了名字。

### 设置项

- **喝水提醒**：默认 45 分钟一次；浅睡时照常弹（人就在电脑前），深睡时攒着，醒来补弹。
- **睡觉阈值**：默认无交互 5 分钟浅睡、全局空闲 10 分钟深睡。
- **纪念日**：填名称＋日期，启动时说"距离 XX 还有 N 天"，一天只会说一次；点它有 10% 概率被"偷偷告诉"。
- **高 DPI 适配**：改完要重启。

图片都放在 **`image\`** 子目录里。查找顺序是 **`image\` → 脚本同目录 → `assets\` → 当前工作目录**；`image\` 排第一，是为了避免你把原图丢在程序目录根下时把正式素材顶掉（2026-10-25 踩过这个坑）。

**素材要求**：建议 600×600、RGBA 透明底、**脚底基线和 idle 一致**。白底图需先用下面的导入工具处理，直接放入会显示白方块。

### 补帧导入（一条命令）

在仓库根目录运行。导入工具只依赖 **Python 3.9+ 和 Pillow**，不需要 PyQt5、显示器或 AI 抠图服务；运行桌宠另需 `python -m pip install PyQt5`。

```powershell
python -m pip install -r requirements-import.txt
python import_frames.py --out walk_test --fit per-frame
```

不提供输入时，默认读取脚本旁 `source/cat_walk_*_src.jpg`（仓库已提供 4 张原图），生成 `walk_test/cat_walk_1.png` 至 `cat_walk_4.png` 和深色底 `walk_preview.png`。检查预览后，可写入桌宠素材目录并重启：

```powershell
python import_frames.py --fit per-frame --overwrite
```

`python import_frames.py` 本身也可运行，但默认输出 `image/` 已有帧时会拒绝覆盖并提示；需显式选择新输出目录或加 `--overwrite`。

也可导入自己的单帧素材（白底或透明底）：

```powershell
python import_frames.py "D:\Download\新帧" --out walk_test
python import_frames.py a.png b.png c.png --fit per-frame --out walk_test
python import_frames.py image/cat_walk_1.png image/cat_walk_2.png --no-cut --out walk_test
python import_frames.py --help
```

| 参数 | 默认 / 实际行为 |
|---|---|
| 输入图片 / 文件夹 | 可混用；文件夹仅扫描当前层 PNG/JPG/JPEG/WebP/BMP，按自然编号排序（2 在 10 前）；显式文件按命令行顺序，重复路径去重。每张图须是一个姿态，不切分拼图；合计 1–8 张，与桌宠加载上限一致 |
| `--out DIR` | 默认脚本旁 `image/`；相对路径相对于当前工作目录 |
| `--fit uniform` | 默认。所有帧用同一缩放比例，保留原始相对大小；适合同一套尺寸的素材 |
| `--fit per-frame` | 每帧分别适配，尽可能统一内容高度；适合独立生成、取景大小不同的图片 |
| `--no-cut` | 保留原有 alpha，跳过白底与阴影处理；用于已抠好的透明图，不会把白底自动变透明 |
| `--white-threshold 240` | 0–255，RGB 三通道均达到该值时视为白底候选；降低会移除更多浅色背景 |
| `--shadow-threshold 210` | 0–255，图像下半部的浅灰候选（最大/最小通道差 ≤12）；0 禁用此阴影规则 |
| `--overwrite` | 允许替换输出，成功导入后删除同目录中超出本次帧数的旧 `cat_walk_1..8.png`，避免短序列混入旧帧；禁止原地覆盖输入。不会改动 idle 或其他动作素材 |

处理流程：保留原有透明度 → 仅去除与画布边界连通的白色 / 下半部浅灰候选 → 按 alpha 裁内容边界 → 保持宽高比缩放 → 水平居中 → 脚底对齐 → 编号保存并生成预览。输出与运行时共用 `frame_geometry.py` 标准：**600×600、最大内容高 482、内容下边界 549（最后可见行 y=548）、水平中心 300**。宽尾巴会优先缩小以完整放入画布，因此内容高度可能小于 482；`uniform` 下较矮姿态也会保留高度差。

**处理限制**：这是浅色背景的连通区域阈值处理，不是通用主体分割。封闭在轮廓内的白毛会保留；与背景连通的白毛、浅色轮廓仍可能被删。浅灰地面阴影只有满足上述规则且连到边界时才会去除，深色或与主体粘连的阴影需手工抠图后用 `--no-cut`。基线按可见内容底部对齐，无法识别爪子；请检查预览中的绿线和轮廓。原图保留在输入目录，仓库自带 PNG 不会被静默替换。

## 评价

### 做得还行的地方

- **架构是干净的**：状态机（idle/walk/sleep/deep_sleep）＋ 帧选择（`_frame()`）＋ 渲染（`paintEvent`）三层分开，加新帧只动 `_frame()` 一处；加新状态只动 `_set_state`。
- **可测性意外地好**：所有状态都是实例属性、所有行为都是方法，不用模拟鼠标就能调 `_on_click()/_enter_sleep()/_start_walk()`，13+11 项回归全是"直接调方法 + 断言状态"。这是能连着改四轮不翻车的根本原因。
- **失败路径都留了余地**：缺图退化成简笔画、mask 建失败退化成整窗可点、单实例抢不到锁也照常运行、异常日志限流不刷屏。
- **性能有实测背书**：mask 重建 7.3ms→0.14ms、2x 重绘 0.59ms→0.059ms、空闲 CPU 0.69%、深睡 0.00%、冷启动 0.28s。不是"感觉快了"。
- **细节开始像"产品"了**：气泡贴头顶 6px、被摸有专门的表情和台词、名字贯穿启动语/喝水提醒/菜单/设置标题。

### 还不够好的地方

- **素材是短板，不是代码**：这轮 4 帧走位卡在"拼图里猫和隔壁尾巴粘连"，说明生成工作流不稳定——单帧一次出（像最早那 3 帧）比一张拼图稳得多。
- v2.2 起代码已拆进 `ragdollpet/` 包（`config / assets / bubble / pet / frames` 等），单文件时代已结束；想加功能按模块改，别再往一个文件里堆。
- **帧动画的物理感弱**：走路匀速平移，没有起步/停下缓动、没有身体起伏。加个 `QEasingCurve` 包络能明显改善。
- **资源路径有三处候选**（exe 旁 / 脚本目录 / assets / cwd），"找不到图为啥"不好查，理想是启动时打一条解析日志。
- **配置已是 JSON**：`pet.json` 在程序目录，备份只拷一个文件；但它是个人配置，已加入 `.gitignore`，别提交进仓库。
- **测试是脚本不是 CI**：得手动跑，没有 pytest 化。

### 一句话

**从"能跑的玩具"变成了"能长期挂着、坏了知道去哪查"的工具。** 代码层面该填的坑基本填完了，现在瓶颈在素材（帧数和一致性），不在实现。真要再往前一步，优先级是：**稳定的 4–6 帧素材 > 走路缓动 > 拆模块**。
